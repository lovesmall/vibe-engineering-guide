# UI/UX 设计规则

本文件写给 AI 编码助手。只要任务涉及界面（新页面、新组件、改样式、加动效），先读完本文件再动手。规则来源：Refactoring UI（Adam Wathan & Steve Schoger）的原则，加上 Linear、Arc 等成熟产品体现出的做法：克制、有节奏、动效服务于理解。

## 0. 怎么使用本文件

- 规则分三级：
  - **必须**：不满足就不算完成。
  - **默认**：没有明确理由就照做；偏离时在 PR 描述里写一句理由。
  - **可选**：锦上添花，按场景决定。
- 本文件里的数值是默认值。项目已有设计系统或 UI 组件库时，以项目的为准，不要另起一套；只在项目没有定义的地方使用本文件的数值。
- 所有尺寸、颜色、时长都从第 2 节的 token 里取。**必须**不在组件里写任意数值（例如 `margin: 13px`、`#3a7bd5`、`transition: 0.37s`）。
- 规则互相冲突时，按这个顺序取舍：可用性与可访问性 > 层级清楚 > 全局一致 > 美观 > 愉悦感。例如，点睛特效影响了操作速度，就去掉特效。
- 写完界面后，按第 10 节截图并逐条自检，在 PR 描述里附上截图（亮色、暗色、手机宽度各一张）。

### 做界面的步骤

1. **判断产品类型**：工具型（每天高频使用，例如项目管理、后台）还是内容型、营销型（阅读、浏览、转化）。它决定密度（第 3 节第 6 条）和动效的多少（6.1）。
2. **找现有系统**：查看项目里已有的 token、主题配置、组件库。有就复用，没有就按第 2 节建立。
3. **用灰度做出层级**：先只用灰色和字重，把主要内容、主要操作、次要信息排好（第 3、4、5 节）。
4. **补全状态**：每个组件的交互状态，每个数据区域的空、加载、错误状态（第 8 节）。
5. **上色与动效**：最后加强调色、动效，以及（如果合适）一处点睛特效（第 5、6、7 节）。
6. **截图自检**：按第 10 节截图、逐条检查，修改后再交付。

## 1. 总原则

1. **先做功能，再做布局。** 从一个具体功能（例如"搜索航班"）开始设计，而不是先画导航栏、侧边栏、页脚这些外壳。
2. **层级优先于装饰。** 每个界面先回答"用户第一眼该看哪里、第二眼看哪里"，再用字重、颜色、间距表达这个顺序。装饰（阴影、渐变、插画）只在层级清楚之后添加。
3. **系统优先于个例。** 先定义有限的选项（间距、字号、颜色、时长），再在选项里挑。选择越少，界面越统一，决策越快。
4. **克制。** 一个界面只有一个主要操作、一种强调色、一个视觉焦点。拿不准的时候选择更少的元素、更多的留白、更弱的装饰。
5. **动效为理解服务。** 动效回答"这个东西从哪来、到哪去、刚才发生了什么"。回答不了这些问题的动效，不加。

### 参考产品的特征

下面两个产品用来校准"好"的样子。提到"做成 Linear 那样"或"Arc 那种感觉"时，指的是这些特征，而不是照抄它们的界面。

- **Linear**（工具型的标杆）：中性灰为主、低饱和、只有一种强调色；紧凑但对齐严格、节奏统一；细描边和很轻的阴影；键盘优先，有命令面板和随处可见的快捷键提示；动效快而轻，几乎感觉不到存在，但每次状态变化都很连贯。
- **Arc**（愉悦感的标杆）：界面退到后面，把空间留给内容；允许用户自定义主题色，产品有"属于我"的感觉；拖拽、展开等直接操作使用自然的弹性动画；在少数时刻放一些有趣的小细节，让人会心一笑，但从不拖慢操作。

## 2. 设计 token（先定系统）

新项目没有设计系统时，先建立下面这套 token（CSS 变量、Tailwind 配置或组件库主题都可以），再写页面。

### 2.1 间距

以 4px 为基数，只用这些值：

`4  8  12  16  24  32  48  64  96  128`（单位 px）

- 相邻的值至少差约 25%。不要出现 `20` 和 `24` 这种难以区分的选择。
- 组件内部用小值（4–16），组件之间用中值（16–32），页面区块之间用大值（48–128）。

### 2.2 字号与行高

| token | 字号 | 行高 | 用途 |
| --- | --- | --- | --- |
| xs | 12 | 16 | 辅助说明、标签、时间戳 |
| sm | 14 | 20 | 工具型界面的正文、表格、按钮 |
| base | 16 | 24 | 内容型界面的正文 |
| lg | 18 | 28 | 引导文字、小标题 |
| xl | 20 | 28 | 卡片标题 |
| 2xl | 24 | 32 | 区块标题 |
| 3xl | 30 | 36 | 页面标题 |
| 4xl | 36 | 40 | 营销页标题 |
| 5xl | 48 | 48 | Hero 标题 |

- 这组数值与 Tailwind CSS 的默认间距和字号一致。项目用 Tailwind 时，直接用对应的类名（如 `p-4`、`gap-6`、`text-sm`），不写 `p-[13px]` 这样的任意值。
- 中文标题的行高至少取字号的 1.3 倍，表中 4xl、5xl 的行高对中文偏紧。
- 中文大段正文用 16px 配 28px 行高（Tailwind 写作 `text-base leading-7`），不用表中 base 的 24px，见 4.2 节。
- 一个页面**默认**最多使用 4 种字号。
- 字重只用 2–3 种：常规（400）、中等（500）、粗（600 或 700）。**必须**不用 300 以下的细体做正文。

### 2.3 颜色

- **灰色**：9–10 级，从接近白到接近黑。灰色带一点色相（偏冷或偏暖，饱和度 5%–10%），比纯灰更有质感。正文**必须**不用纯黑 `#000`，用最深一级灰。
- **主色**（强调色）：1 个，5–9 级深浅。只用在主要操作、选中状态、链接、焦点环上。
- **语义色**：成功（绿）、警告（黄/橙）、危险（红）、信息（蓝），每种 3–5 级。
- **文字三级**：主要文字、次要文字、弱化文字，用灰色的三个深浅表示，不用透明度叠在彩色背景上。
- 推荐用 OKLCH 定义色阶，让同一级的不同色相看起来亮度一致。

### 2.4 圆角、阴影、层级

- 圆角选一种风格并全局统一：锐利（2–4px）、适中（6–8px）或圆润（12–16px）。嵌套元素的圆角 = 外层圆角 − 内边距，否则角会显得不贴合。
- 阴影 3–5 级，对应元素离页面的"高度"：
  - 1 级：按钮、输入框（几乎看不见）
  - 2 级：卡片、下拉菜单
  - 3 级：弹出层、Popover
  - 4–5 级：对话框、命令面板
- 每级阴影由两层组成：一层小而深（模拟直接遮挡），一层大而淡（模拟环境光）。光源固定在正上方偏上，所以阴影 y 偏移为正、x 偏移为 0。

### 2.5 时长与缓动

| token | 时长 | 用途 |
| --- | --- | --- |
| instant | 0–80ms | 颜色、背景的 hover 变化 |
| fast | 120–150ms | 按钮按下、开关、复选框、tooltip |
| base | 200–250ms | 下拉菜单、Popover、Tab 切换 |
| slow | 300–400ms | 对话框、抽屉、页面级过渡 |

| token | 曲线 | 用途 |
| --- | --- | --- |
| ease-out | `cubic-bezier(0.16, 1, 0.3, 1)` | 进入画面的元素（默认） |
| ease-in | `cubic-bezier(0.7, 0, 0.84, 0)` | 离开画面的元素 |
| ease-in-out | `cubic-bezier(0.65, 0, 0.35, 1)` | 已在画面里的元素移动、变形 |
| spring | 刚度高、阻尼适中、无明显回弹 | 拖拽、手势、跟随指针的元素 |

**必须**不用 `linear` 做 UI 位移动画（加载进度条、旋转图标除外）。

## 3. 布局

1. **从多留白开始，再往回收。** 先给到明显"太多"的间距，再逐步减到合适。AI 生成的界面最常见的问题是太挤。
2. **用间距表达分组。** 同组元素之间的间距**必须**明显小于组与组之间的间距（**默认**至少 2 倍）。标签和它的输入框要更靠近彼此，而不是更靠近上一个字段。
3. **不必填满屏幕。** 内容需要多宽就给多宽。表单、设置页**默认**最大宽度 480–640px；正文阅读区每行 45–75 个字符（`max-width: 65ch` 左右，中文约 35–40 字）。宽屏上剩余空间留白，或放次要信息。
4. **对齐到网格和基线。** 元素左边缘对齐；同一行的文字基线对齐（不同字号并排时用 `align-items: baseline`）。
5. **少用边框分隔。** 想分开两块内容时，按顺序考虑：加大间距 → 背景色差 → 阴影 → 最后才是边框。一个区域里同时有边框、阴影、背景色三种分隔，**必须**删掉至少一种。
6. **密度按产品类型选，选定后保持一致。** 工具型产品（像 Linear）可以紧凑：正文 13–14px、列表项高度 32–36px。内容型和营销页要宽松：正文 16–18px、区块间距 64–128px。同一个产品里不要混用两种密度。
7. **响应式从窄屏开始。** 先写 375px 宽的布局，再往宽处扩展。**必须**在 375px 下没有横向滚动条，触控目标不小于 44×44px。

## 4. 排版与节奏（Typography & Rhythm）

### 4.1 层级

- 用**字重和颜色**区分层级，而不是只放大字号。标题粗一点、正文用主要文字色、辅助信息用次要文字色，往往比把标题放大到 32px 更有效。
- 想突出一个元素，先考虑**弱化周围的元素**，而不是加强它本身。
- 标签（label）和数值并排时，数值是重点，标签弱化；很多时候标签可以完全去掉（例如 "¥128" 不需要再写"价格："）。
- 次要和第三级操作用文字按钮或描边按钮，不要每个按钮都做成实心主色。

### 4.2 行高与字距

- 大段阅读的正文（文章、说明、评论）行高 1.5–1.6，中文 1.7–1.8：英文用表中的 base（16/24），中文用 16/28。
- 工具型界面里的短文本（表格单元格、标签、按钮、单行列表项）可以更紧，用表中的 sm（14/20，约 1.43）。
- 标题行高 1.1–1.3。字号越大，行高比例越小。
- 行越长，行高越大；窄栏可以紧一点。
- 大标题（≥ 30px）字距略收紧（`letter-spacing: -0.01em` 到 `-0.02em`）；全大写的小标签字距放宽（`0.05em`）并缩小字号。

### 4.3 垂直节奏

- 所有 margin、padding、gap 都从间距 token 取值，这样整页的空白会形成规律的节奏。
- 标题离下方内容近、离上方内容远（例如上 32、下 12），让读者看出标题属于下面那段。
- 段落间距约等于正文行高（16px 正文配 16–24px 段距）。
- 列表、表格行使用统一的行高，不因内容不同而高低不齐。

### 4.4 文字细节

- 数字列、价格、计时器用等宽数字：`font-variant-numeric: tabular-nums`。
- 文本**必须**左对齐（居中只用于很短的标题、空状态、营销页 Hero）；不用两端对齐，除非同时开启断字。
- 中文：不用斜体表示强调，用字重或颜色；中英文、中文与数字之间留空格（或使用 `text-autospace`）；字体栈把系统中文字体放在西文字体之后，例如 `"Inter", "PingFang SC", "Noto Sans SC", system-ui, sans-serif`。
- 截断要可恢复：被截断的文字**必须**能用鼠标、键盘和触屏查看全文，例如点击进入详情、展开按钮，或可以聚焦触发的 tooltip。`title` 属性只能作为补充，因为它只在鼠标悬停时出现。

## 5. 颜色与深度

1. **先用灰度设计，最后上色。** 先只用灰色把层级做对；颜色是最后一步，用来强调和表达状态。
2. **一个界面一种强调色。** 主色只出现在当前最重要的一到两处。
3. **不只靠颜色表达状态。** 错误、成功、选中状态**必须**同时有图标、文字或形状的变化，照顾色弱用户。
4. **对比度达标。** 正文与背景对比度**必须** ≥ 4.5:1，大字（≥ 24px，或 ≥ 18.66px 粗体）和图标 ≥ 3:1。
5. **彩色背景上的次要文字**，用同色相的浅色或深色，不用灰色，也不用白色加透明度。
6. **暗色模式不是反色。** 暗色背景用深灰（不是纯黑），层级越高的表面越亮；阴影在暗色下效果很弱，用更亮的表面色和细描边表达层级；饱和色要降低饱和度。
7. **用深度表达交互性。** 凸起（有阴影、比背景亮）表示可点击；凹陷（内阴影、比背景暗）表示可输入。

### 5.1 图标与图片

- 全产品只用一套图标库，统一线宽和风格。图标尺寸跟随旁边的文字：14px 文字配 16px 图标，16px 文字配 20px 图标，图标与文字垂直居中对齐。
- **必须**不把为小尺寸设计的图标放大到 48px 以上当插画用。需要大图形时，把小图标放进有背景色的圆形或方形容器里，或者使用专门的插画。
- 文字压在图片上时，**必须**保证对比度：加半透明深色遮罩、渐变遮罩，或者降低图片的亮度和饱和度。
- 用户上传的图片要固定容器尺寸和比例（`aspect-ratio` + `object-fit: cover`），并给浅色图片加一圈很淡的内描边，避免图片边缘融进背景。
- 图片加载前先占好位置（写明宽高或比例），避免布局跳动。

## 6. 动效

### 6.1 什么时候加动效

只在以下三种情况加：

1. **反馈**：确认用户的操作被接收了（按下、切换、提交成功）。
2. **连续性**：说明元素从哪里来、到哪里去（菜单从按钮展开、卡片展开成详情、删除的项收起后列表补位）。
3. **引导注意**：把视线引到刚刚变化的地方（新消息、校验错误）。

以下情况**必须**不加或极短：

- 高频操作：键盘快捷键、命令面板、Tab 切换、列表导航。用户每天做几百次的操作，动效 ≤ 150ms 或者直接没有。
- 会阻塞输入的动画：动画进行时用户必须能继续点击、输入。
- 纯装饰的循环动画（漂浮、呼吸、持续闪烁），除非它表示"正在进行"的状态。

### 6.2 怎么做

- 只动 `transform` 和 `opacity`。**必须**不对 `width`、`height`、`top`、`left`、`margin` 做动画；尺寸变化用 `transform: scale` 或 FLIP / View Transitions API。
- 进入用 ease-out，离开用 ease-in，且**离开比进入快**（约为进入时长的 60%–75%）。
- 位移距离小：弹出层从 4–8px 外滑入，配合透明度，而不是从屏幕边缘飞进来。缩放从 0.95–0.98 开始，不从 0 开始。
- 弹出层的变换原点（`transform-origin`）对准触发它的元素。
- 按下反馈：按钮 `:active` 时缩小到 0.97–0.98，时长用 fast。这是成本最低、效果最明显的反馈。
- hover 效果放在 `@media (hover: hover)` 里，避免在手机上点击后 hover 状态"粘住"。
- 列表依次出现（stagger）时，每项间隔 20–40ms，整组总时长 ≤ 300ms；超过 10 项后，后面的不再错开。
- 直接操控（拖拽、滑动、拉伸）用 spring，并且可以被打断：用户中途改方向时，动画从当前位置和速度继续。
- **必须**支持 `prefers-reduced-motion: reduce`：去掉位移和缩放，只保留透明度变化或直接切换。

### 6.3 加载与等待

- 操作在 300ms 内完成，**不显示**任何加载状态，避免闪烁。
- 300ms–1s：在触发的位置显示轻量指示（按钮内的小 spinner、禁用按钮）。
- 超过 1s：用和最终内容形状一致的骨架屏（skeleton）；超过 10s：显示进度或预计时间，并允许取消。
- 能预测结果的操作（点赞、勾选、改名）用乐观更新：先更新界面，失败再回滚并提示。

## 7. 点睛特效（Cherry on Top）

点睛特效的目的是让人愉悦，但它只是锦上添花。规则：

1. **数量**：整个产品 1–3 处，不多于此。
2. **位置**：放在低频但有意义的时刻：完成一个重要任务、第一次成功、达成里程碑、空状态、引导流程的最后一步。**必须**不放在高频路径上。
3. **时长**：一次性效果 ≤ 1.5s，不打断用户继续操作，不需要用户关闭。
4. **可退出**：遵守 `prefers-reduced-motion`；会持续出现的效果提供关闭开关。
5. **性能**：不掉帧（60fps），优先用 CSS；粒子类效果用 canvas 并限制粒子数量；不为了一个特效引入大体积依赖。

可以参考的做法：

- 完成任务时的少量彩纸或对勾描线动画。
- 数字变化时的滚动计数（例如统计值从旧值滚到新值）。
- 按钮或卡片 hover 时，跟随光标的柔和高光。
- 拖拽时带一点阻力和回弹，松手后元素有重量感地落位。
- 有个性的空状态插画或一句文案。
- 主题色、壁纸等由用户自己定制（Arc 的做法），让产品有"属于我"的感觉。

## 8. 交互与状态

1. **每个可交互组件都要设计全部状态**：默认、hover、focus、active（按下）、disabled、loading。数据区域还要有：空状态、加载中、错误、部分数据。**必须**不交付只有"正常状态"的界面。
2. **焦点必须可见。** 用 `:focus-visible` 显示清晰的焦点环（2px，主色，带 2px 偏移）。**必须**不写 `outline: none` 而不提供替代。
3. **键盘可用。** 所有操作都能用键盘完成；对话框打开时焦点移入、关闭后回到触发元素；`Esc` 关闭弹出层。工具型产品**默认**为核心操作提供快捷键，并在菜单或 tooltip 里展示。
4. **触控目标**：桌面端 ≥ 24×24px，移动端 ≥ 44×44px。视觉上小的图标按钮，用 padding 扩大可点击区域。
5. **空状态是引导机会。** 说明这里会出现什么，并给出第一步操作的按钮，而不是只写"暂无数据"。
6. **错误信息说人话**：说清楚发生了什么、用户该怎么做；显示在出错的位置旁边；不清空用户已经填写的内容。
7. **破坏性操作**：优先提供撤销（Undo，toast 中保留 5–10s）；无法撤销的操作才用确认对话框，确认按钮上写明动作（"删除项目"，而不是"确定"）。
8. **按钮文案用动词**，说明点击后会发生什么（"保存修改"、"发送邀请"）。

## 9. 反模式（AI 生成界面的常见问题）

看到下面这些，就说明界面需要修改：

| 反模式 | 改成 |
| --- | --- |
| 紫蓝渐变背景、渐变文字、霓虹光晕，没有品牌理由 | 中性灰背景加一种强调色 |
| 卡片套卡片，每块都有边框 + 阴影 + 圆角 | 用间距和背景色分组，只在最外层保留一种分隔 |
| 所有内容居中对齐 | 左对齐，只有 Hero 和空状态居中 |
| 用 emoji 当图标 | 使用统一图标库（如 Lucide、Phosphor），同一套线宽和尺寸 |
| 每个按钮都是实心主色 | 一个主要按钮，其余用次要、文字按钮 |
| 页面上出现 6 种以上字号 | 收敛到 3–4 种，用字重和颜色区分层级 |
| 灰色文字放在彩色背景上 | 用同色相的浅色或深色文字 |
| 间距随手写（13px、22px、30px） | 从间距 token 取值 |
| 所有元素同时淡入、或者每个元素都有入场动画 | 只给发生变化的部分加动效 |
| 动效 500ms 以上、带明显回弹 | 150–300ms，ease-out，无回弹 |
| 用 Lorem ipsum 或 "Item 1、Item 2" 做占位 | 用贴近真实的内容，包括长文本、空值、极端数字 |
| 只设计了"数据刚好"的情况 | 同时检查空数据、一条数据、超长文本、上千条数据 |

## 10. 交付前自检清单

AI 看不到自己写出的界面，所以**必须**先截图再检查，不凭代码想象效果：

- 用 Playwright（或项目已有的端到端测试工具）打开页面，至少截取三张：1280px 宽亮色、1280px 宽暗色、375px 宽。
- 看截图检查层级、对齐和间距；交互状态（hover、focus、打开的菜单、错误提示）也各截一张。
- 用 axe-core 等工具自动检查对比度和可访问性问题。
- 对照下面的清单逐条确认，在 PR 描述中附上截图，并列出没有满足的项及原因。

**系统**

- [ ] 所有间距、字号、颜色、圆角、阴影、时长都来自 token，没有任意数值
- [ ] 页面字号不超过 4 种，字重不超过 3 种
- [ ] 只有一种强调色，且只用在最重要的地方

**布局与排版**

- [ ] 一眼能看出主要内容和主要操作
- [ ] 组内间距明显小于组间间距
- [ ] 大段正文行宽不超过 75 个字符（中文约 40 字），行高符合 4.2 节
- [ ] 375px 宽度下无横向滚动，触控目标 ≥ 44px

**颜色与可访问性**

- [ ] 文字对比度 ≥ 4.5:1（大字 ≥ 3:1）
- [ ] 状态不只靠颜色表达
- [ ] 焦点环可见，所有操作可以用键盘完成
- [ ] 亮色和暗色模式都检查过

**动效**

- [ ] 每个动效都属于"反馈、连续性、引导注意"之一
- [ ] 只动 transform 和 opacity，时长和缓动来自 token
- [ ] 高频操作没有拖慢的动效，动画不阻塞输入
- [ ] 支持 `prefers-reduced-motion`

**状态**

- [ ] 每个组件都有 hover、focus、active、disabled、loading 状态
- [ ] 数据区域有空状态、加载状态、错误状态
- [ ] 用超长文本、空值、大量数据测试过
