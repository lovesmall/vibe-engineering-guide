# Vibe Engineering 指南

一份关于“如何和 AI 一起做出可靠软件”的实践指南。

## 这份指南想解决什么问题

用 AI 写代码（常被叫作 vibe coding）让做出第一版变得很快，但很多项目随后会卡在同样的地方：需求没对齐就开始写、出了错说不清影响和原因、没有测试、上线后没人维护。

这份指南把“vibe coding”往“vibe engineering”推进一步：保留 AI 带来的速度，同时补上工程上该有的纪律。它回答两个问题：

1. 你应该怎样和 AI 协作，才能让它的产出可控、可验证、可维护？
2. AI 应该遵守哪些规则？这些规则写在 [`AGENTS.md`](AGENTS.md) 里，可以直接复制到你自己的项目中使用。

## 适合谁读

- **产品经理 + 工程师型的人**：有一定技术基础，懂业务和产品，但不一定精通当前项目用的编程语言，希望借助 AI 独立把产品做出来。
- **用 AI 编程的个人开发者和小团队**：已经在用 Claude Code、Copilot 等工具，想让项目从“能跑”走到“能上线、能维护”。
- **想给团队制定 AI 协作规范的人**：需要一份可以直接落地的规则模板。

不太适合：只想找某个 AI 工具的操作教程，或者想深入学习某门编程语言的读者。

## 怎么使用

- **直接用规则**：把 [`AGENTS.md`](AGENTS.md) 复制到你的项目根目录，大多数 AI 编程工具会自动读取它（部分工具使用 `CLAUDE.md` 等文件名，可按需改名或引用）。
- **理解规则背后的原因**：阅读下面各章，了解每条规则要解决的问题、常见的反面例子，以及怎样按自己的情况调整。

## 目录

> 各章正在编写中，标题和顺序可能会调整。

1. **沟通原则**：怎样和 AI 对齐需求；先讲业务和功能，再讲技术；出错时按“影响、原因、解决方案”的顺序沟通。
2. **设计**：写代码之前先确认业务流程和数据结构；解耦与关注点分离；为维护和扩展而设计。
3. **开发与测试**
   - 平台与 UI：选择 LTS 运行时和成熟的 UI 组件库
   - 编码：统一术语；把外部依赖当作不可靠的（超时、重试、熔断、幂等）；以官方文档为准
   - 测试：单元/功能测试加端到端测试，覆盖关键流程和边界情况
   - PR 与代码审查：自我复查、Copilot review 循环，以及什么时候该停下来重新审视设计
4. **部署**：从零搭建 staging；staging 与生产同代码、不同配置；用独立资源隔离环境。
5. **维护**：交付时附上维护方案；用 Agent 或定时任务自动打补丁；线上出问题时先止血、再根治。
6. **附录：`AGENTS.md` 规则全文与逐条说明**
